# Критерії оцінювання (Залік / Незалік) — Домашнє завдання №2

> У колонці "Як зараховується" спочатку вказано МІСЦЕ (файл або конкретна сторінка/вкладка/секція сайту), а потім — що саме там має бути.

| № | Критерій | Як зараховується |
| --- | --- | --- |
| — | **✅ Обов'язкові** | — |
| 1 | Перехід на AGENTS.md (корінь репозиторію) | Файлова система, корінь репо: ЄСТЬ `AGENTS.md` → поруч має лежати symlink `CLAUDE.md`→`AGENTS.md` АБО `CLAUDE.md` з одним рядком-імпортом `@AGENTS.md`. Немає `AGENTS.md` — критерій просто не застосовується |
| 2 | Перехід на AGENTS.md (server/client/reviewer-core) | Файлова система, папки `server/`, `client/`, `reviewer-core/`: той самий патерн (rename + symlink/import), не лише в корені |
| 3 | Скіл UI-архітектури | Файлова система: `.claude/skills/frontend-architecture/SKILL.md` (назва папки орієнтовна). Вміст: де сторінки (app-router), де компоненти сторінки, де спільні компоненти, naming-конвенції, де тести |
| 4 | Скіл Onion-архітектури | Файлова система: `.claude/skills/onion-architecture/SKILL.md`. Вміст: шари роут→сервіс→домен через контейнер, зовнішні інтеграції в адаптерах на краю, залежності всередину, заборона виклику адаптера напряму з роута |
| 5 | Скіл pr-self-review існує | Файлова система: `.claude/skills/pr-self-review/SKILL.md`, тип Workflow (диспетчер скілів) |
| 6 | Agents у сайдбарі SKILLS LAB | Лівий сайдбар: пункт **Agents** знаходиться в секції SKILLS LAB, а не WORKSPACE |
| 7 | Сторінка Agents — сітка/список карток | Сайдбар SKILLS LAB → сторінка **Agents**: показує список/сітку плиток (карток) усіх агентів |
| 8 | CRUD над таблицею skills | Backend: `GET/POST/PUT/DELETE /skills[:id]` реально читають/пишуть у Postgres (перевірка: створити скіл через API → знайти запис у БД напряму запитом; видалити напряму в БД → `GET /skills` більше його не повертає) |
| 9 | Сторінка Skills — сітка карток | Сайдбар SKILLS LAB → сторінка **Skills**: список карток скілів, кожна — назва, тип, опис, перемикач «увімкнено» |
| 10 | Клік по картці → прев'ю збоку | Сторінка **Skills**: клік по картці скіла зі списку відкриває прев'ю в БІЧНІЙ панелі (side panel), а не в модалці й не на окремій сторінці |
| 11 | Кнопка «додати» скіл | Сторінка **Skills**, кнопка «Додати»/«+»: відкриває вибір «створити» або «імпортувати»; саме створення відбувається в модалці |
| 12 | Форма скіла | Модалка створення скіла (кнопка «додати» → «створити»): поля назва, опис, тип, тіло в markdown |
| 13 | Вкладка Skills у редакторі агента | Сайдбар SKILLS LAB → сторінка **Agents** → відкрити конкретного агента → вкладка **Skills**: прив'язка скілів, увімкнення/вимкнення, зміна порядку (drag&drop) |
| 14 | Drag&drop на вкладці Skills агента реально впливає на промпт | Це не просто UI-косметика: порядок, у якому скіли розставлені через drag&drop на вкладці Skills агента (критерій 13), — саме в цьому порядку їхні тіла вставляються в системний промпт при запуску агента. Перевірка: переставити скіли місцями в UI → запустити агента → в зібраному промпті (лог/трейс прогону) блоки скілів теж помінялись місцями |
| 15 | Імпорт скіла з файлу/zip-архіву | Сторінка **Skills** → «додати» → «імпортувати»: приймає .md файл АБО саме .zip-архів (інші формати архівів — .tar/.rar/.7z — підтримувати не обов'язково); показує прев'ю ядра скіла перед збереженням |
| 16 | Хоча б один скіл через імпорт | Сторінка **Skills**: хоча б один зі скілів, прив'язаних до нових агентів, має походження "імпортовано" (не просто "створено") |
| 17 | Контрольний експеримент — Test Quality | Сторінка PR, кнопка Run Review: прогнати Test Quality Reviewer на PR з тестом лише на happy-path БЕЗ прив'язаного скіла → не флагує; той самий PR, скіл прив'язаний → флагує непокриту гілку й межовий випадок |
| 18 | Контрольний експеримент — API Contract | Так само: PR зі зміною сигнатури роуту, без скіла → пропуск; зі скілом → виявляє breaking change |
| 19 | Скіли в трасі промпта | Сторінка PR → вкладка Agent runs → Review runs → відкрити трасу прогону (іконка логу/трейсу): секція збірки промпта показує окремий блок скілів + число поруч із ним — "скільки токенів важить саме цей блок" ("токени рахуються не вручну — беремо весь текст скілів, що потрапили в цей блок, і рахуємо його токенізатором (напр. tiktoken) АБО найпростіше — приблизно, за формулою `довжина_тексту / 4`; головне, щоб це число стосувалося САМЕ блоку скілів, а не всього промпта цілком") |
| 20 | Увімкнено/вимкнено видно в логах | Той самий трейс прогону: увімкнений скіл — окремий блок у логах; вимкнений скіл — блоку немає взагалі |
| 21 | pr-self-review — ручний виклик на змішаний diff | Локально (Claude Code): автовиклик (hook на git push) вимкнений; ручний запуск скіла на diff, що зачіпає і client/, і server/, підтягує обидва набори скілів одночасно |
| 22 | Картка скіла — версія і кількість агентів | Сторінка **Skills**, картка скіла: крім назви/типу/опису/тоглу — ще поточна версія і лічильник кількості агентів, до яких прив'язаний (agent_count) |
| 23 | Кнопка «Видалити» на картці скіла | Сторінка **Skills**, картка скіла: є кнопка "Видалити" |
| 24 | Підтвердження видалення скіла | Клік "Видалити" на картці скіла: відкривається модалка (підтвердити / скасувати / хрестик) |
| 25 | Вкладки сторінки скіла | Сторінка **Skills** → клік на скіл → сторінка `/skills/:id`: вкладки Config, Preview, Versioning (вкладка Stats — не обов'язкова, буде в ДЗ №8) |
| 26 | Preview — рендерений вигляд | Сторінка `/skills/:id` → вкладка **Preview**: показує форматований (рендерений) вигляд тіла скіла, не сирий markdown-текст |

| 28 | Кнопка Diff у версіях | Та сама вкладка **Versioning**, кожна попередня версія: кнопка "Diff" показує різницю з поточною версією |
| 29 | Кнопка Restore у версіях | Та сама вкладка **Versioning**: кнопка "Restore" повертає тіло скіла до обраної версії |
| 30 | Пошук у Skills-табі агента | Та сама вкладка **Skills** сторінки `/agents/:id`: поле пошуку/фільтрації скілів за назвою |
